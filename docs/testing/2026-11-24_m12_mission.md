# M12 - mission management (simulation) - 2026-11-24

Package `mecanum_forklift_task_manager` (`mission_manager`): `ExecuteMission` action (PALLET_TRANSPORT: pick dock, drop dock, optional return pose)
over Nav2 `NavigateToPose` and `DockPallet`; ROS-free state machine `mission_core.MissionRunner` + thin ROS wrapper; `MissionStatus` topic (2 Hz and on change).
Policies (confirmed): retryable `STAGING_FAILED` / `MARKER_NOT_FOUND` / `NAV_FAILED` (1 retry each), everything else ends the mission; timeouts 150 s navigation,
180 s dock, 600 s mission (node clock = sim time); one mission at a time (a second goal is accepted and aborted at once with `BUSY`); cancel is propagated to the
active child goal and the robot is confirmed stopped; fork is left where it is.

## What was added besides the manager
- **Drop** (`DockPallet` dock entry with `operation: drop`, dock `pallet_drop_1` = sim dropoff station pad). With a pallet and its box on the forks the fork-mounted
  camera looks into the load (the first marker-based drop failed with MARKER_NOT_FOUND), so the drop uses map-frame poses from the database: Nav2 to `staging_pose`
  (loaded footprint), holonomic alignment to `final_pose` (AMCL), lower, reverse 0.30 m by dead reckoning, bare footprint back, map with the pallet at its new place
  (`simple_warehouse_nav_pallet_1_dropped`, generated with `make_nav_map.py ... pallet_1,box_1 <added objects>`). New error code `NOT_CARRYING`, state `LOWERING`.
- Interfaces: `ExecuteMission.action`, `MissionStatus.msg` (new dependency `geometry_msgs` of the interfaces package).
- Dev tools: `scripts/mission_trials.py`, `scripts/mission_failures.py`, `drop_check.py`, `dev_stack.sh start_mission|stop_mission|stop_dock|start_dock`.

**Criterion revision**: the plan said "within 3 cm of the pad centre". The drop is placed by AMCL (map frame) and lands 4-7 cm off, almost all along the approach axis
(sideways <= 2 cm), which is AMCL's own accuracy (3-7 cm, see M8/M9). The pad is 0.42 m long and the pallet 0.20 m, so the pallet is always fully on the pad; the
criterion is now "fully on the pad, centre within 8 cm". A tighter drop needs a sensor that sees the target with the load on the forks (not a fork-mounted camera).

## Failure injection (10 cases, all PASS; every case: robot stopped, no active child goal)
| case | expected | result |
|---|---|---|
| unknown dock / drop dock used as pick dock | INVALID_MISSION at VALIDATE, robot does not move | PASS |
| marker hidden | 1 retry, then MARKER_NOT_FOUND at PICK | PASS (2 PICK attempts) |
| box on the staging pose | STAGING_FAILED (after 1 retry) or TIMEOUT at PICK | PASS (STAGING_FAILED) |
| lift target above the limit | LIFT_FAILED at PICK, no retry | PASS |
| cancel during PICK / DROP / RETURN | CANCELED at that step | PASS (DROP: pallet still on the forks, z 32 mm = fork held) |
| second mission while one is active | BUSY, first mission unaffected (then cancelled) | PASS |
| mission limit 45 s | MISSION_TIMEOUT | PASS (landed in RETURN) |
| mission node killed (SIGINT) mid-pick | child goal cancelled, no orphan goal, robot stopped | PASS |

## Test-harness lessons
- A cancelled pick can leave the robot with its forks at the pallet, inside painted obstacle cells; Nav2 then cannot plan out, so the next reset failed. The reset now drives back with teleop and checks the pose.
- Expectations: a blocked staging pose is aborted by Nav2 when the box is seen from the start (STAGING_FAILED); Nav2 only fails to give up (-> TIMEOUT) when the obstacle appears later; a full mission takes only ~50-65 s of sim time.

## Not verified / open
- Only pallet_1, one pick dock and one drop dock; fixed poses; no queue, no persistence (the manager forgets everything on restart; the workflow's `carrying` flag also resets, a drop after a restart is refused with NOT_CARRYING).
- Teleop during a mission is not tested (it pre-empts navigation through twist_mux and may make the mission fail or time out).
- Drop accuracy limited by AMCL; no payload realism (sim 0.5 kg); machine power losses made long runs batch-wise. Simulation does not establish physical safety.
